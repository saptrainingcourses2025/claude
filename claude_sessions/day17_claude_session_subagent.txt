● Project Survey Report

  1. CDS Entities (db/)

  Main entities (db/schema.cds):
  - Destinations — cuid. No associations.
  - Travellers — cuid, managed. Compositions: locations (TravelledLocations),
  addresses (Addresses). Associations: type (TravellerTypes), status
  (TravellerStatus, default 'A'), addressType (AddressTypes). modifiedAt 
  @odata.etag, virtual fullName.
  - TravelledLocations — cuid. Associations: traveller, destination. Has cost +
  currency with @Measures.ISOCurrency.
  - Addresses — cuid. Associations: traveller, addressType. Has isPrimary
  boolean.

  User/Auth entities:
  - Users — cuid. Composition: roles (UserRoles). Fields: loginName, isLocked.
  - UserRoles — cuid. Associations: user, role (many-to-many join).
  - UserCredentials (db/auth.cds) — cuid. Association: user. Fields:
  passwordHash, failedAttempts, lastLoginAt.

  Code lists (db/common.cds, all sap.common.CodeList):
  - AddressTypes (H/O/P/T), TravellerStatus (A/I/S), Roles
  (ADMIN/AGENT/TRAVELLER), TravellerTypes (FF/EX/ST).

  2. Services (srv/)

  Service: CatalogService (cat-service.cds)
  Path: catalog
  @requires: authenticated-user
  Notable: Row-level @restrict — non-admins see only their own data (userID = 
    $user.email). Exposes Travellers, TravelledLocations, Addresses + 4
  read-only
     code lists. No custom actions.
  ────────────────────────────────────────
  Service: AuthService (auth-service.cds)
  Path: auth
  @requires: any
  Notable: Actions: login, refresh, register. Function: me. Returns
  LoginResponse
    / UserInfo / RegisterResponse types.
  ────────────────────────────────────────
  Service: PublicService (public-service.cds)
  Path: public
  @requires: any
  Notable: Read-only Destinations catalog.
  ────────────────────────────────────────
  Service: UserManagement (user-management.cds)
  Path: user-management
  @requires: ADMIN
  Notable: Exposes Users, Roles, UserRoles. Functions: lockUser, unlockUser.
    Actions: createUser, resetPassword, assignRole, unassignRole.

  3. UI Apps (app/)

  managetravel — SAPUI5 freestyle:
  - Views: App, Login, TravellerDashboard, AdminDashboard + BaseController.
  - Routes: "" → login, "admin" → admin, "traveller" → traveller.
  - Fragments: Header, RegisterDialog, TravellerProfile, TravelledLocationsTab,
  AddressesTab, SpendDonutChart, AdminTravellersTable, AdminAddressesTable.
  - Data sources: catalog + user-management OData V4.

  managedest — Fiori Elements (List Report / Object Page):
  - Routes: DestinationsList, DestinationsObjectPage.
  - Annotations in annotations.cds. Extends sap.fe.core.AppComponent. Hits
  public OData V4.

  4. Custom Handlers (srv/handlers/)

  - auth.handler.js → AuthService: login (bcrypt compare, JWT issuance),
  refresh, register (creates Users + UserCredentials + default Traveller,
  isLocked=true), me.
  - travellers.handler.js → CatalogService: before CREATE/UPDATE validation
  (firstName/lastName/email uniqueness, auto-fill userID), after READ computes
  virtual fullName.
  - travelled-locations.handler.js → CatalogService: before CREATE validates
  date order + checks overlapping trips (409 on conflict).
  - user-management.handler.js → UserManagement: lock/unlock, createUser (with
  bcrypt), resetPassword, assignRole/unassignRole.

  5. Auth Implementation

  - srv/auth/jwt.js — HS256 JWTs. Secret from AUTH_JWT_SECRET (random hex in
  dev). Access TTL 15m, refresh TTL 7d. Audience claim distinguishes access vs
  refresh.
  - srv/auth/jwt-auth.js — Express middleware (wired via cds.requires.auth.impl
  in package.json). Decodes Bearer token, looks up user in Users table, checks
  isLocked, loads roles, populates cds.User. 401 on invalid, 403 on locked.
  - srv/auth/password.js — bcryptjs, cost 10. hash() + compare().
  - srv/init/role-init.js — Seeds ADMIN/AGENT/TRAVELLER roles on
  cds.on('served').
  - srv/init/user-init.js — Seeds default admin anubhav@anubhavtrainings.com /
  Welcome1! on served.
  - srv/server.js — Bootstraps the two init scripts.
  - No xs-security.json — pure custom JWT (dev-mode).

  6. .http Test Files

  - srv/travel-app-tests.http (~894 lines) — 10 sections: metadata, Destinations
   CRUD, Travellers (with ETag/If-Match), TravelledLocations (overlap
  validation), value helps, $expand chains, UserManagement admin flows, $batch,
  OData V2 compat, $filter/$orderby/$top. Uses @jwt variable.
  - srv/role-tester.http (~177 lines) — RBAC tests: admin flow, traveller flow
  (row-level filtering via where-clause), 403/401 negative tests, UserManagement
   admin assertions. Uses @adminJwt + @userJwt.
  - material/day11/travel-app-tests.http (~876 lines) —
  Archived/training-material variant of the main test file, slightly older code
  values.

  ---
  Highlights: 3-service split (Catalog / Auth / Public + admin UserManagement),
  JWT auth via custom middleware (no XSUAA), row-level security through
  @restrict where userID = $user.email, dual UI apps (freestyle for app, Fiori
  Elements for destination catalog), default admin auto-seeded at startup.
